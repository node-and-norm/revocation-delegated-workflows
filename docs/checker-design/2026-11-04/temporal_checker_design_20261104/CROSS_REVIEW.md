# Cross-review before specification integration

4 November 2026. Source/specification comparison only. No implementation or experiment. Compared `INDEPENDENT_CHECKER_DESIGN.md` with `../temporal_checker_spec_20261104/CHECKER_ACCEPTANCE_SPEC.md`.

## Required corrections

1. **Make treatment requirements case-specific.** Acceptance A03 unconditionally requires cancellation observation and observation-to-release-to-execute links. K1/K2 deliberately have no cancellation. C1 has no execute in the proposed strict schedule. C4 intentionally has its effect before the cancellation request. Apply A03's continuation chain only to M1–M4. Define separate required/forbidden/optional events for every case family. Otherwise correct controls are rejected or misleadingly marked not-applicable without a frozen reason. A02 should likewise expressly apply native schedule/start/terminal requirements only to native cells, not any sink-only K controls.

2. **Do not silently strengthen C1 or invent C4 precision.** A06 and T01 require zero C1 execute attempts. Current protocol says zero effects and “no sink attempt required”; candidate cooperative code does imply no bridge call. Zero attempts is a sensible proposed qualification expectation but requires an explicit reviewed schedule decision, not a claim that the protocol already mandates it. My design's C4 one historical attempt and zero later attempts is also a proposal needing freeze. C4's present source candidate is not implemented, so its terminal schedule cannot be inferred from existing continuation code.

3. **Repair T08's ambiguity.** “Consistently alter request/run/attempt mapping” is not always invalid. A bijective renaming of opaque IDs across all records and the frozen synthetic manifest must preserve the verdict, as the acceptance spec's own metamorphic property says. Invalid variants should specify cross-run substitution against an unchanged manifest, broken schedule/start linkage, duplicated operation identity, or changing attempt 1 to 2. Separate provenance tampering under an unchanged manifest from semantic mutation under a newly valid synthetic manifest. This distinction prevents checksum rejection from masquerading as semantic checking.

4. **Separate unresolved facts from unsupported positive assertions.** T18's hidden true fence with no visible evidence should yield a caller's reference classification `unresolved`. If the caller instead asserts a positive fence confirmation, that assertion is `unsupported` and fails A10; it is not itself merely an unresolved assertion. Keep factual reference outcome and assertion-support verdict distinct. The same distinction applies to hidden effects and native terminal outcomes.

## Integration refinements

5. **Adopt the acceptance spec's explicit cleanup eligibility gate.** My design separates cleanup from primary facts but does not explicitly include acceptable cleanup in its eligibility conjunction. Use the acceptance spec's rule: cleanup errors may block overall qualification acceptance while leaving established primary sink/native facts intact. They must never retroactively rewrite those facts. Exact “acceptable cleanup” categories belong in the frozen manifest, not an operator's judgment after seeing results.

6. **Retain the stronger coordinated-cut specification without overstating what an offline checker proves.** The two designs agree that no global atomic snapshot is available. Adopt a declared stable interval, linked cut acknowledgments, per-source boundaries, one SQLite read transaction and certification before release/shutdown. The checker can validate saved capture evidence; it cannot independently detect every omitted commit, fabricated capture receipt or dishonest producer. Under trusted-fixture assumptions, an unobserved concurrent mutation remains a limitation, not a cryptographic guarantee. Acceptance T15 correctly labels the concurrent-commit scenario a proposed capture test rather than a general offline race detector. If implementation remains prohibited, keep T15 as a specification, not a test to execute now.

7. **Refine my F16 late-effect test.** A cleanup-only effect cannot be merged into primary results. It invalidates a claimed stable cut only when its dispatch/mutation violates the certified interval or contradicts the certificate's assertion that no pending fixture dispatch remained. A new separately authorized operation strictly after the bounded interval does not retroactively falsify an earlier bounded no-effect finding. The fixture must explicitly place the late effect on the same previously pending operation.

8. **Qualify C4 preservation language.** Linked prior and later rows can support that the same historical effect is present at both observed cuts, and therefore no observed rollback of that row. Uninterrupted persistence between cuts or the absence of every intervening mutation additionally needs the complete ledger/boundary contract. T21 should name which claim is scored rather than using “preservation” for all three.

9. **Use merged provenance accurately.** My initial design used the inspected local verification record at historical commit `381ce452…`, not the current merged head. The acceptance spec reports GitHub-verified merged commit `5ceceb4…` and its controlling reconciliation. In integration, the latter should be the controlling provenance, attributed to that verification; retain the historical record only as antecedent evidence. I did not independently fetch the merged commit and should not be credited with doing so.

10. **Carry over complementary requirements.** Acceptance spec adds unsafe-path rejection, unsupported-field handling, explicit measured inclusion/exclusion reasons and effective configuration allowlists; retain these. My design adds lossless protobuf ID decoding, complete receipt/result and effect-row/event bijections, wrong-denial rejection, distinct no-request/no-observation categories and 30 test vectors; retain these where not redundant. No additional runtime claims follow from this merge.

The current protocol's no-effect category is already present; the remaining enum-name mismatch must still be reconciled before freeze. No original source or previously denied patch was changed during this review.
