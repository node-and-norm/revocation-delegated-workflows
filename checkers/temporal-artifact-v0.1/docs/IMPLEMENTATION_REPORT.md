# Artifact-only checker implementation report

5 November 2026. Proposal v0.3 implementation, version 0.1.0.

## Delivered scope

A standard-library Python checker reads saved, registered local artifacts. It never imports or starts the Temporal runtime, Worker, gateway, bridge or controller. It contains no network driver. No remote repository was changed, and no native qualification or measured collection occurred.

Implemented components:

- Strict bounded JSON/JSONL parsing, duplicate-key rejection, finite numbers, neutral artifact identities, safe paths, byte lengths and SHA256 checks. Unsupported versions and unknown semantic fields fail closed.
- A documented synthetic-only native schema with lossless integer IDs, run/attempt linkage, ordered pagination tokens, complete-prefix declarations and separate Activity/Workflow observations.
- Read-only immutable SQLite inspection of the historical gateway's actual table format. Execute receipts, terminal outcomes, effect events and effect rows are reconciled in both directions. Raw positive facts survive failed controls.
- Per-phase causal graphs, no wall-clock causal inference, case-specific C1/C4/M/K schedules, separate configuration defects and observed deviations, and capture/cleanup checks.
- P1/P2 isolation and P3 contradiction checks. Later evidence cannot repair a missing primary cut. A linked later commit can contradict a claimed resolved dispatch; unrelated later operation IDs do not falsify the earlier bounded interval.
- Exact synthetic raw-to-canonical A/B file and field projection, source-reference validation, byte-identical underlying paired views, and separate scoring of envelope claims and projection claims. Permitted weaker Activity observations remain supportable when stronger native evidence is withheld.
- Six-category scoring, undefined support rate when there are no determinate claims, fixed planned opportunities, and explicit missing-phase availability. Sink-only controls have P1 and seven fields, with no fabricated native lifecycle.

## Validation evidence

The project unittest suite contains 115 distinct test methods, with no network or native execution. Saved positive fixtures cover the six measured-plan-shaped cells plus C1 and C4 in both native modes: ten synthetic fixtures, not ten experimental observations. Their exact expected rule statuses and score counts appear in `fixtures/catalog.json`.

The measured-plan-shaped synthetic subset has 94 planned field opportunities per view. The supplied generated projections produce 89 correct determinate and five justified unresolved outputs in each view. The five unresolved outputs are receipt-backed fence confirmation where no fence exists; the contract has no determinate “not confirmed” value. These are deterministic fixture checks, not scientific accuracy or comparative benefit estimates.

Both A and B synthetic claims are generated by the same reference helper. Their equality verifies this packaging and scoring implementation, not an independently implemented native baseline, human review, usability benefit, or experimental result. Adversarial tests use separately specified exact assertions rather than treating generated “success” flags as ground truth.

The independent AI-assisted reviewer developed and executed a separate regression harness. Its final hash-bound review and results are included in `review/`. This is not independent human validation.

The preserved partial Q2 SQLite snapshot was also read without modifying its bytes. It contains zero execute receipts and zero effect rows. This establishes only those saved contents. It has no complete v0.3 capture certificate or native evidence and does not become a successful control or a bounded no-effect conclusion. See `reports/saved_q2_snapshot_inspection.json`.

## Explicit incomplete requirements

1. **Production exporter and native adapter:** not implemented or qualified. The synthetic normalized schema is intentionally rejected as evidence of native execution. Real Temporal payload encodings, namespace/run export details, version-pinned native schema paths and exporter mappings remain open.
2. **Independent runtime phase sealing:** not implemented. The fixture registry seals the complete saved fixture, including combined producer records. It is not proof that P1 was independently persisted before release. A runtime exporter must create immutable per-phase registries and producer-prefix artifacts. The report exposes this as an unobserved freeze requirement.
3. **Observed native outcome mappings:** no native tuple has been qualified. Synthetic test oracles, if supplied, are explicitly labeled and cannot make `native_qualification` true.
4. **Numerical deadlines and timing enforcement:** the saved fixtures keep all runtime budgets unset. The checker can reject invalid budget values but does not implement or calibrate a monotonic runtime deadline instrument. Local observer anchors, margins, hold budget and emergency procedure remain open.
5. **Full freeze/measurement readiness:** not established. Source/runtime pins beyond the synthetic adapter's supported SDK and historical gateway identity, production capture guarantees, native transport behavior and measured collection need separate permitted qualification and review.
6. **Authentication and hostile-producer defenses:** not claimed. Hashes and consistent certificates do not prove authentic or complete production evidence. The checker validates the supplied trusted-fixture representation.

`qualification_acceptance` and `execution_readiness` remain unobserved, and `native_qualification` is false on every supported bundle. A CLI exit code of zero means a report was generated, not that qualification passed.

## Review-driven corrections

The preserved review records document fixes for malformed registry objects, nonfinite numeric overflow, wrong run/start references, unsafe or ambiguous graph identities, A/B byte equality, phase-local parsing, cancellation-call correlation, historical-effect acknowledgment linkage, hidden weaker evidence, wrong-denial fact preservation, capture accounting, and nested envelope leakage.

No prior research artifact, source candidate, denied operation or empirical result was modified or rerun. Further native work must remain separate from this artifact-only development package.
